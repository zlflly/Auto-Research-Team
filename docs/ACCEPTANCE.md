# 宿主验收清单（尚未执行）

本清单用于真实 Codex 客户端；不能用本地测试中的 `fixture-*` 标签替代实际 agent IDs。工具测试通过不等于以下项目通过。

| 检查 | 操作 | 通过标准 |
|---|---|---|
| 可发现性 | 在受信任的小型测试项目安装，开新会话 | 实际 picker 或 `/skills` 出现入口，无重复技能，无未知 manifest 字段错误 |
| 原生组织 | 给一个小工程目标并允许使用现有本地测试 | 能观察到真实 Engineer 与不同 Verifier 线程；Owner 记录实际 IDs，而非角色文字模拟 |
| Insight | 同时提供聊天假设与一个现存 md | 原文/字节保留；区分约束与待测假设；结果可以反驳 insight |
| 接入项目 | 让 Owner 使用现有测试/benchmark | 评估适配器执行真实命令，日志可追踪；没有把固定数值 fixture 当成用户研究结果 |
| 工程验收 | 给一个新增功能或可复现 bug | baseline_expected_failures 预声明；baseline 可保留原有失败，candidate 完整通过；回归未被豁免 |
| 算法验收 | 给便宜且有参考实现的算法优化任务 | 正确性先于速度；baseline/candidate 同协议；独立确认可重跑；不以一轮噪声作正结论 |
| evaluator 完整性 | 在隔离测试项目更改冻结 evaluator | helper 拒绝使用不匹配证据，Owner 不悄悄重冻协议 |
| 版本绑定 | 在独立验证后修改 candidate | 原验证不再通过；对新版本重新验收 |
| 单槽与预算 | 启动两次受控运行，或用小 run budget | 第二个同时运行被拒；失败也消耗额度；预留确认预算没有被搜索占用 |
| 恢复 | 暂停非终态任务，再次显式恢复 | 先检查实际线程/进程，不复跑未确认停止的任务；沿用准确下一步 |
| 汇报节奏 | 连续进行几次便宜实验/返修 | 内部记录落盘，不逐轮找人搬运反馈；必要预算/权限/目标决策仍升级；用户请求状态能立即读台账 |
| 结项卡 | 完成或得出无收益/证据不足 | 有支持范围、baseline 对比、证据路径、代码版本、残余限制；没有活跃遗留任务 |

建议使用隔离、无敏感凭证的小项目完成接入验收。多智能体工具可能显示进度；这不算 Owner 主动逐条报告。若并发或长期执行能力受客户端限制，记录能力边界，而非降低科研验证口径。

实际试用时记录每个任务的人工审查时间、抽检漏错、总成本，区分“少看消息”与“少做验证”。本版不预设相对已有流程的性能提升。

## 0.1.1 仓库管理宿主验收增量（待真实宿主执行）

1. 两个真实 Engineer 被分派至不同 A/B 目录；核对 cwd、明确写范围和 lease epoch，不以角色名代替隔离证据。
2. 原用户 checkout 的 HEAD、index 和已有未提交文件保持原样；全局/共享 Git 配置不被子角色改写。
3. Engineer yield → Owner seal → 授权 runner 的真实交接可审计；评估期间原 writer 没有继续改源码。
4. 改代码复用旧 node 拒跑；新 node 可复用原槽位，旧 run 仍引用旧快照。
5. Verifier 从独立真实线程读取封存源码，接管原槽位执行 matched confirmation；不加第三个写工作区。
6. 中断后核对线程、租约、作业与 snapshot/node 状态，不因一次不确定的进程查询而启动重复评估。
7. 归档确实包含可恢复的声明源码、配置、冻结 evaluator/manifest 与原始结果；外部数据/环境限制明确。
8. 真实任务评估应比较人工审查耗时、漏错和成本；本地 fixture 通过不证明这些指标改善。
